Rabbit Relay keeps configuration explicit and close to RabbitMQ concepts.
You configure defaults on the broker, then override them per queue/exchange
interface when needed.

## RabbitMQ connection URL

Rabbit Relay reads the connection URL from the `RABBITMQ_URL` environment
variable:

```bash
RABBITMQ_URL=amqp://user:password@localhost:5672
```

Or override it per broker:

```ts
const broker = new RabbitMQBroker("orders-service", {
  connectionUrl: "amqp://user:password@rabbitmq.internal:5672",
  connectionName: "orders-service-primary",
  shutdownTimeoutMs: 30_000,
});
```

Each broker owns its own connection; closing one broker never closes another
broker's resources.

## Topology ownership mode

Decide **who owns RabbitMQ topology**:

<Tabs items={['assert', 'passive', 'plan-only']}>
  <Tab>

```ts
// App declares everything (default)
const broker = new RabbitMQBroker("orders-service", {
  topologyMode: "assert",
});
```

  </Tab>
  <Tab>

```ts
// Terraform/Helm/definitions own it — relay only checks existence
const broker = new RabbitMQBroker("orders-service", {
  topologyMode: "passive",
});
```

  </Tab>
  <Tab>

```ts
// CI/docs inspect the plan without touching the broker
const broker = new RabbitMQBroker("orders-service", {
  topologyMode: "plan-only",
});
```

  </Tab>
</Tabs>

<Callout title="Infrastructure-managed deployments">
  Prefer `topologyMode: "passive"` over the legacy `passiveQueue` flag.
  `passiveQueue` remains supported but only controls main-queue declaration.
</Callout>

## Publisher confirms

Disabled by default. Enable when the publisher must know that RabbitMQ
accepted the message:

```ts
const pub = await broker
  .queue("orders.q")
  .exchange("orders.ex", { publisherConfirms: true });
```

## Message size guard

```ts
const broker = new RabbitMQBroker("orders-service", {
  maxMessageBytes: 256 * 1024,
});

// override per publish
await sub.publish(envelope, { maxMessageBytes: 64 * 1024 });
```
